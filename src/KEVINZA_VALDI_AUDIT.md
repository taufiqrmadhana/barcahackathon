# Kevinza-Valdi branch audit

**November 16 update:** the complete 5 Hz cache now reproduces the README's
0.9125 training-window spellF1. See [the new reproduction](KEVINZA_2026_11_16.md).
The results below retain the sparse cache used on November 15.

Reviewed `origin/feat/kevinza-valdi` at
`81e220d6ec81aa30fe72f4e36c4d8a3465dcb482` on 2026-11-15, while staying on `taufiq`.
The commit changes two files: HSMM fusion and tree/model selection settings.

Its new ideas are confidence-dependent video evidence, an additive 0.15 weight on
legacy v2 evidence, and 500-tree ExtraTrees/RandomForest classifiers with minimum
leaf size 2. Classifier selection trades off log-loss against sample macro-F1.

## Standalone reproduction

An isolated archive of that revision used the existing original `film` cache:
1,257 samples, including 537 public samples. No feature values were overwritten.
The branch's default physical/v2 configurations and this command were used:

```bash
OMP_NUM_THREADS=3 OPENBLAS_NUM_THREADS=3 python src/run_v3.py run \
  --sets v2+flow+film --out results
```

ExtraTrees was selected. The run took 220 seconds.

| Output | macroF1 | spellF1 | Public possessions |
|---|---:|---:|---:|
| Standalone physical baseline | 0.8631 | 0.5143 | 11 |
| Branch's printed out-of-fold result | 0.8106 | 0.4000 | 16 |
| Branch's written CSV, public portion | 0.9529 | 0.7862 | 12 |

The CSV is generated by `Layer.proba(..., oof=False)`: its public predictions come
from a classifier fitted to all public labels. It therefore cannot be compared to
Taufiq's held-out public CSV. The branch's printed OOF calculation is separate;
it stitches probabilities before decoding and uses a 50-frame purge. Taufiq uses
a 125-frame purge and independent whole-half decoding per held-out classifier.
The standalone branch also uses a different physical baseline and sample grid.

The reported score of approximately 0.91 could not be reproduced from the revision
and cache available here. Its original cache, command and metric were not provided;
these results do not establish what that reported number measured.

## Adaptations with Taufiq's evaluation

The adaptations keep macro-v2's physical baseline, two video views, aligned five
time folds, 1 Hz training samples, five-second purge, bounded dead-ball edits,
and independent fold decoding. Only the indicated idea changes.

| Adaptation | macroF1 | spellF1 |
|---|---:|---:|
| Macro v2 checkpoint | **0.9491** | **0.7529** |
| Confidence power 2 + v2 blend 0.15 | 0.9472 | 0.7412 |
| Confidence power 2 only | 0.9473 | 0.7412 |
| v2 blend 0.15 only | 0.9484 | 0.7529 |
| Confidence power 1 only | 0.9481 | 0.7294 |
| ExtraTrees, 34 continuous/video features | 0.9408 | 0.6667 |
| ExtraTrees, those features + 20 LOOP features | 0.9371 | 0.6250 |
| ExtraTrees, branch's 55-feature specification | 0.9228 | 0.5625 |

None improves the current macro-F1 checkpoint. Their settings are not enabled in
the default pipeline. The audit is reproducible with the existing macro-v2 model
and its video caches:

```bash
OMP_NUM_THREADS=3 OPENBLAS_NUM_THREADS=3 .venv/bin/python src/bench/kevinza_bench.py
```

Aggregate results and input fingerprints are in
`bench/results/kevinza_valdi_2026-11-15.json`. Model/parameter selection still reuses
the same 17 public possessions; these are not private or unseen-match results.
